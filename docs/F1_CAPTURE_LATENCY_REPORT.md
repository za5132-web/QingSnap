# F1 截图唤出延迟优化

> 发布归档说明：以下保留各轮本地试用时的范围、测量和未发布状态记录。用户确认后，相关最终改动纳入 v1.1.5；当前发布内容与边界以 RELEASE_NOTES_v1.1.5.md 为准。

日期：2026-11-05。基于 v1.1.4 及尚未发布的贴图缩放、文字样式修复。版本不变；本次只交付本地试用，不推送、打标签或替换 GitHub 发布资产。

## 分析与实现

截图路径为：全局快捷键 → CaptureCoordinator → 抓取鼠标所在屏幕 → 构造 CaptureOverlayWindow → 首次布局和显示。用户当前截图延时设置为 0；显式设置的延时仍然保留。

1. **减少桌面图像中转。** 保留现有 CopyFromScreen，每次都抓取最新桌面；将新建 GDI Bitmap 的像素直接复制为冻结的 WPF BitmapSource，不再额外创建 HBITMAP 再转回 WPF。LockBits 必须在 finally 中释放，源 Bitmap/Graphics 仍然立即 Dispose。采用 Bgr32，忽略桌面抓取中不可靠的 alpha 字节，避免黑图或透明桌面。
2. **一次性空闲预热。** 主窗口创建后，在 ApplicationIdle 用 1×1 内置白像素构造同一截图控件树，以 64×64 小画布进行离屏布局和渲染，然后关闭。没有 Show/EnsureHandle，不显示窗口，不读取桌面、访问剪贴板、保存历史或启动 OCR。预热失败记录日志，正常截图仍可进行。不保留蒙层窗口或桌面缓存，不新增常驻定时器。
3. **首帧优先。** 初始智能窗口探测放到 Background 优先级，让布局/渲染先运行；鼠标移动和智能识别功能保留。极快单击先于延后探测时，同步补一次原生探测，不能因此丢失智能选区。关闭后回调检查已关闭状态。SourceInitialized 仅定位物理窗口，不通过 SWP_SHOWWINDOW 提前重入显示，首次显示由现有 Window.Show 负责。
4. **首帧后的耗时日志。** CaptureLatency 记录屏幕抓取、控件构造和 ContentRendered 的耗时。日志写入在首帧事件后执行，仅有时间，不包含画面、进程标题或文件路径。首帧/关闭时均解绑一次性事件。

未修改快捷键绑定、DPI 换算、显示器选择、负坐标规则、历史范围、标注行为、OCR 引擎和已有贴图动效修复。未新增设置和依赖。

## 本机测量

以下为短样本，不能代表所有机器，不能把 ContentRendered 等同于显示器光学呈现完成。

### 隔离诊断程序

同一 Release 诊断程序测量屏幕抓取，但仅将合成图像显示在蒙层中，不显示/保存所抓取的真实桌面。firstFrame 包含窗口构造，不包含前面的抓屏时间。

| 样本 | 优化前抓屏 | 优化前 firstFrame | 优化后抓屏 | 优化后 firstFrame |
|---|---:|---:|---:|---:|
| 首次 | 159.10ms | 937.97ms | 101.09ms | 358.39ms |
| 随后 1 | 62.10ms | 246.35ms | 37.91ms | 168.73ms |
| 随后 2 | 57.57ms | 200.51ms | 45.78ms | 196.95ms |
| 随后 3 | 52.31ms | 219.30ms | 49.38ms | 213.50ms |

本组首次抓屏+首帧约 1097ms → 459ms，改善主要来自把初始化移到空闲时；随后测量有波动，未宣称所有调用都有同样比例提升。另一轮优化后首次合计约 358ms。一次空闲预热约 315～358ms，仍在 UI 线程运行，因此它不是零开销：软件刚启动且立即操作时仍需特别验证响应。

诊断另外检查：预热后 Application.Windows 数量回到初始值；蒙层实际 HWND 物理坐标和尺寸与 snapshot 完全一致。仅实际验证本机屏幕布局，未冒充完成全部多 DPI/多屏组合。

## 人工检查项

1. 重启程序，空闲约一秒后 F1；连续取消/重试，对比第一次和后续响应。也测试刚启动立刻 F1。
2. F1 后不移动鼠标，确认智能框出现；立即单击确认采用智能区域；自由拖框仍然正常。
3. Esc 取消；Enter/双击确认；F2、Ctrl+Z/Y、F3、Shift+F1 与 R 五范围循环仍按原行为。
4. 切换浅/深主题；在 100%、150%、200% 显示器和负坐标副屏检查蒙层全覆盖、取色与物理选区精确。
5. 设置截图延时后确认仍按设置等待，改回立即后无额外人为延时。
6. 截图后复制、贴图、OCR、长截图入口继续可用；前轮贴图缩放与收纳保持效果。
7. 如果仍感到慢，收集新的 CaptureLatency 计时；优先区分屏幕抓取、UI 初始化、热键排队或智能识别，不凭主观感觉继续盲改显示架构。
